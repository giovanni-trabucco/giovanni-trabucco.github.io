Building LibTorch for 32-bit ARM, with QNNPACK quantization

PyTorch doesn't ship LibTorch for 32-bit ARM, so I built it myself, with QNNPACK turned on so it can run quantized (int8) models. I did this in April 2025. These are the steps that worked for me, and I later went through all of them again from scratch to make sure.

PyTorch 2.1.0 · ONNX Runtime 1.19.2 · Protobuf 21.12 and 3.13.0 · built on a Jetson Orin

1What we're building

The goal is LibTorch, the C++ part of PyTorch, as shared libraries (libtorch.so and friends) for an armv7 board with hard-float (armhf). I also built ONNX Runtime because I needed it on the same board. You can skip that part if you only want LibTorch.

I didn't build on the board. I built on a Jetson Orin (aarch64, Ubuntu 20.04) and cross-compiled for 32-bit ARM. The Jetson has one handy property: it can run 32-bit ARM programs. That matters because the build needs to run a tool called protoc that it compiles itself.

The order is:

  1. Protobuf 21.12, then ONNX Runtime on top of it.
  2. Protobuf 3.13, the older version PyTorch wants.
  3. A small patch to PyTorch, plus some helper tools.
  4. LibTorch itself.
  5. A tiny test program.

Yes, two versions of Protobuf. ONNX Runtime needs 21.12 and PyTorch 2.1 needs 3.13. They can't share one.

Why these versions

The model I run on the board is quantized to int8. I trained it with quantization-aware training (FX graph mode, using the qnnpack settings), then exported it to TorchScript. On the board, the quantized layers run on QNNPACK, PyTorch's backend for quantized ops on ARM. That's why the build turns it on with USE_PYTORCH_QNNPACK.

I trained the model with PyTorch 2.0 on a Jetson, using NVIDIA's build. LibTorch should be at least as new as the PyTorch you export with, so I picked 2.1.0, the nearest stable release after it.

2What you need

Two cross compilers. This surprised me, but it's the setup that works:

  • The Arm GNU toolchain 11.2 (arm-none-linux-gnueabihf) for PyTorch.
  • Ubuntu's own arm-linux-gnueabihf-gcc-9 for both Protobufs and ONNX Runtime.

Why? The build runs the protoc we compile. If it's compiled with GCC 11.2, it needs a newer C library than Ubuntu 20.04 has, and it refuses to start (GLIBC_2.34 not found). Compiled with Ubuntu's GCC 9, it runs fine.

shell
# Arm toolchain 11.2, from developer.arm.com
sudo tar -xJf gcc-arm-11.2-2022.02-aarch64-arm-none-linux-gnueabihf.tar.xz -C /opt
export PATH=/opt/gcc-arm-11.2-2022.02-aarch64-arm-none-linux-gnueabihf/bin:$PATH

# Ubuntu's GCC 9 cross compiler
sudo apt install gcc-9-arm-linux-gnueabihf g++-9-arm-linux-gnueabihf

# other tools
sudo apt install git build-essential python3 python3-pip
pip3 install pyyaml typing_extensions

A recent CMake. The one in Ubuntu 20.04 (3.16) is too old. I used 3.31, installed with pip3 install --user cmake.

Time and disk. The whole thing took about 5 hours on the Jetson, most of it LibTorch. Keep 15 GB or so free.

3Get the source code

Everything goes in one folder. I use ~/workspace. The config files below use that path, so change them if you pick another one.

shell
mkdir -p ~/workspace && cd ~/workspace

git clone --branch v21.12  https://github.com/protocolbuffers/protobuf.git protobuf
git clone --branch v3.13.0 https://github.com/protocolbuffers/protobuf.git protobuf_pytorch
git clone --branch v1.19.2 https://github.com/microsoft/onnxruntime.git onnxruntime

git clone --branch v2.1.0 https://github.com/pytorch/pytorch.git pytorch
cd pytorch
git submodule update --init --recursive
cd ..

When I went through the steps again later, github.com/microsoft/onnxruntime answered "Repository not found". I used my old local copy, checked out at tag v1.19.2 (commit ffceed9). If the clone fails for you too, you'll need a copy of that tag from somewhere else.

4The toolchain files

A toolchain file tells CMake which compiler to use and that it's building for another machine. I have three.

protobuf_tool.cmake, for both Protobuf builds:

protobuf_tool.cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR arm)

set(CMAKE_C_COMPILER   arm-linux-gnueabihf-gcc-9)
set(CMAKE_CXX_COMPILER arm-linux-gnueabihf-g++-9)

set(CMAKE_CXX_FLAGS "-Wno-error")

onnx_tool.cmake, for ONNX Runtime. It points at the Protobuf 21.12 we'll build in step 5:

onnx_tool.cmake
SET(CMAKE_SYSTEM_NAME Linux)
SET(CMAKE_SYSTEM_VERSION 1)
SET(CMAKE_C_COMPILER   arm-linux-gnueabihf-gcc-9)
SET(CMAKE_CXX_COMPILER arm-linux-gnueabihf-g++-9)

SET(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
SET(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
SET(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
SET(CMAKE_FIND_ROOT_PATH_MODE_PACKAGE ONLY)

SET(ONNX_CUSTOM_PROTOC_EXECUTABLE $ENV{HOME}/workspace/protobuf/install/bin/protoc)
SET(PROTOBUF_INCLUDE_DIRS         $ENV{HOME}/workspace/protobuf/install/include)
SET(PROTOBUF_LIBRARIES            $ENV{HOME}/workspace/protobuf/install/lib)

pytorch_tool.cmake, for LibTorch. It uses the GCC 11.2 toolchain and turns off what I didn't need (CUDA, Python, distributed training):

pytorch_tool.cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR armv7l)

SET(CMAKE_BUILD_TYPE Release)
SET(CMAKE_POSITION_INDEPENDENT_CODE ON)
SET(CMAKE_LIBRARY_PATH /opt/gcc-arm-11.2-2022.02-aarch64-arm-none-linux-gnueabihf/arm-none-linux-gnueabihf/libc/usr/lib)

SET(PYTORCH_QNNPACK_LIBRARY_TYPE static)
SET(PYTORCH_QNNPACK_BUILD_BENCHMARKS OFF)
SET(PYTORCH_QNNPACK_BUILD_TESTS OFF)

SET(CMAKE_C_COMPILER   arm-none-linux-gnueabihf-gcc)
SET(CMAKE_CXX_COMPILER arm-none-linux-gnueabihf-g++)

SET(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
SET(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
SET(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)
SET(CMAKE_FIND_ROOT_PATH_MODE_PACKAGE ONLY)

SET(USE_CUDA OFF)
SET(USE_QNNPACK ON)
SET(USE_PYTORCH_QNNPACK ON)
SET(USE_OPENMP OFF)
SET(USE_MPI OFF)
SET(USE_KINETO OFF)
SET(BUILD_PYTHON OFF)

SET(BUILD_CUSTOM_PROTOBUF OFF)
SET(BUILD_PROTOBUF OFF)
SET(PROTOBUF_UPDATE_FILES ON)
SET(USE_DISTRIBUTED OFF)
SET(USE_TENSORPIPE OFF)

# Protobuf 21.12 (see the note below)
SET(PROTOBUF_PROTOC_EXECUTABLE $ENV{HOME}/workspace/protobuf/install/bin/protoc)
SET(PROTOBUF_INCLUDE_DIRS      $ENV{HOME}/workspace/protobuf/install/include)
SET(PROTOBUF_LIBRARIES         $ENV{HOME}/workspace/protobuf/install/lib)
SET(ONNX_PROTOC_EXECUTABLE     $ENV{HOME}/workspace/protobuf/install/bin/protoc)

# Protobuf 3.13, the one PyTorch actually uses
SET(CAFFE2_CUSTOM_PROTOC_EXECUTABLE $ENV{HOME}/workspace/protobuf_pytorch/install/bin/protoc)
SET(CAFFE2_PROTOBUF_INCLUDE_DIRS    $ENV{HOME}/workspace/protobuf_pytorch/install/include)
SET(CAFFE2_PROTOBUF_LIBRARIES       $ENV{HOME}/workspace/protobuf_pytorch/install/lib)

# helper tools for SLEEF (step 8)
SET(NATIVE_BUILD_DIR $ENV{HOME}/workspace/pytorch/third_party/sleef/sleef_build_host)

I originally thought the 21.12 lines were used for the ONNX code inside PyTorch. They aren't. When I checked the build, PyTorch only ever called the 3.13 protoc. The lines do no harm, and this is the exact file I tested, so I left them in.

5Protobuf 21.12 and ONNX Runtime

shell
cd ~/workspace/protobuf
cp ../protobuf_tool.cmake tool.cmake
mkdir -p build && cd build
cmake .. \
  -DCMAKE_TOOLCHAIN_FILE=../tool.cmake \
  -DCMAKE_INSTALL_PREFIX=$HOME/workspace/protobuf/install \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_POSITION_INDEPENDENT_CODE=ON \
  -Dprotobuf_BUILD_SHARED_LIBS=OFF \
  -Dprotobuf_BUILD_TESTS=OFF
make -j$(nproc)
make install

../install/bin/protoc --version   # should print: libprotoc 3.21.12

If that last command prints a GLIBC error, Protobuf was built with the wrong compiler. Check the toolchain file.

Now ONNX Runtime. One thing needs fixing first. During the build it downloads Eigen from GitLab, and GitLab has re-packed that zip since this version came out. The files inside are the same, but the checksum changed and the download gets rejected. So update the checksum:

shell
cd ~/workspace/onnxruntime
sed -i 's/be8be39fdbc6e60e94fa7870b280707069b5b81a/32b145f525a8308d7ab1c09388b2e288312d8eba/' cmake/deps.txt

cp ../onnx_tool.cmake tool.cmake
mkdir -p build && cd build
cmake ../cmake \
  -DCMAKE_TOOLCHAIN_FILE=../tool.cmake \
  -DCMAKE_BUILD_TYPE=Release \
  -Donnxruntime_BUILD_SHARED_LIB=ON \
  -Donnxruntime_ENABLE_CPUINFO=OFF \
  -Donnxruntime_GCC_STATIC_CPP_RUNTIME=ON \
  -Donnxruntime_RUN_ONNX_TESTS=OFF \
  -Dprotobuf_WITH_ZLIB=OFF
make -j6

This took about half an hour. The result is build/libonnxruntime.so.

6Protobuf 3.13

Same as before. The only difference is that in this older version the CMake files are in the cmake folder.

shell
cd ~/workspace/protobuf_pytorch
cp ../protobuf_tool.cmake tool.cmake
mkdir -p build && cd build
cmake ../cmake \
  -DCMAKE_TOOLCHAIN_FILE=../tool.cmake \
  -DCMAKE_INSTALL_PREFIX=$HOME/workspace/protobuf_pytorch/install \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_POSITION_INDEPENDENT_CODE=ON \
  -Dprotobuf_BUILD_SHARED_LIBS=OFF \
  -Dprotobuf_BUILD_TESTS=OFF
make -j$(nproc)
make install

../install/bin/protoc --version   # should print: libprotoc 3.13.0

7Patch two assembly files in PyTorch

Without this, the LibTorch build stops with:

Error: unknown architecture `armv7-a;'

Two assembly files put .arch armv7-a; .fpu neon on a single line, and the GNU assembler doesn't accept that. Those lines aren't needed anyway, because the compiler already targets armv7-a with NEON. So I just delete the line that uses them.

The two files are in pytorch/aten/src/ATen/native/quantized/cpu/qnnpack/src/q8gemm_sparse/:

  • 4x8c1x4-dq-packedA-aarch32-neon.S
  • 4x8c8x1-dq-packedA-aarch32-neon.S

Open each one in a text editor. Near the top, a few lines define something called NDEF_APPLE_SYMBOLS. Leave those alone. A bit further down (around line 84) there's a line with only this on it:

        NDEF_APPLE_SYMBOLS                                                    ;\

Delete that whole line, and do the same in the other file. That's one line per file, two lines in total. Delete the full line and don't change the lines around it. They all end in \, which joins them into one long definition.

8SLEEF helper tools

SLEEF is a math library inside PyTorch. It needs a few small programs that run on the build machine, not on the board. Build them with the normal system compiler, without any toolchain file:

shell
cd ~/workspace/pytorch/third_party/sleef
cmake -S . -B sleef_build_host \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTS=OFF -DBUILD_DFT=OFF -DBUILD_QUAD=OFF -DBUILD_GNUABI_LIBS=OFF
cmake --build sleef_build_host -j$(nproc)

The NATIVE_BUILD_DIR line in pytorch_tool.cmake points to this folder.

9Build LibTorch

shell
cd ~/workspace/pytorch
cp ../pytorch_tool.cmake tool.cmake
mkdir -p build && cd build
cmake .. \
  -DCMAKE_TOOLCHAIN_FILE=../tool.cmake \
  -DCMAKE_INSTALL_PREFIX=$HOME/workspace/pytorch/install \
  -DBUILD_SHARED_LIBS=ON \
  -DPYTHON_EXECUTABLE=$(which python3)
make -j1
make install

Note the -j1, a single job. When I ran it in parallel on the Jetson the build crashed, so I build one file at a time. It's slow (about 4 hours), but it finishes.

At the end, pytorch/install/lib contains libtorch.so, libtorch_cpu.so, libc10.so and libprotobuf.so.3.13.0.0. All of them are 32-bit ARM. You can check with file libtorch_cpu.so.

10Test it

A tiny program that creates a random tensor and prints it:

main.cpp
#include <torch/torch.h>
#include <iostream>

int main() {
  torch::Tensor t = torch::rand({2, 3});
  std::cout << t << std::endl;
}
CMakeLists.txt
cmake_minimum_required(VERSION 3.18)
project(hello_torch CXX)
set(CMAKE_CXX_STANDARD 17)

find_package(Torch REQUIRED)
add_executable(hello_torch main.cpp)
target_link_libraries(hello_torch "${TORCH_LIBRARIES}")

When you configure it, you have to tell CMake where LibTorch's Protobuf is (Protobuf_DIR). Without that, it stops with "Your installed Caffe2 version uses protobuf but the protobuf library cannot be found".

shell
L=$HOME/workspace/pytorch
cmake -S . -B build \
  -DCMAKE_TOOLCHAIN_FILE=$L/tool.cmake \
  -DTorch_DIR=$L/install/share/cmake/Torch \
  -DProtobuf_DIR=$L/install/lib/cmake/protobuf
cmake --build build -j

On the board, copy over hello_torch and the .so files from pytorch/install/lib, and run it.

You can also try it right on the Jetson. Its own 32-bit C library is too old for programs built with GCC 11.2, so you start the program with the toolchain's loader instead:

shell
T=/opt/gcc-arm-11.2-2022.02-aarch64-arm-none-linux-gnueabihf/arm-none-linux-gnueabihf
$T/libc/lib/ld-linux-armhf.so.3 \
  --library-path $T/libc/lib:$T/lib:$L/install/lib \
  ./build/hello_torch

This is what I got:

 0.4166  0.2232  0.2923
 0.8177  0.7349  0.4586
[ CPUFloatType{2,3} ]

Your numbers will be different, since they're random. If you see a 2×3 tensor, it works.

11Errors I ran into

ErrorWhat to do
GLIBC_2.34 not found when running protocBuild Protobuf with arm-linux-gnueabihf-gcc-9, not GCC 11.2 (step 2).
Eigen download: hash mismatchUpdate the checksum in cmake/deps.txt (step 5).
unknown architecture `armv7-a;'Apply the patch from step 7.
LibTorch build crashes halfwayUse make -j1. It resumes where it stopped.
"the protobuf library cannot be found" in your own projectAdd -DProtobuf_DIR=…/install/lib/cmake/protobuf (step 10).
CMake says your version is too oldInstall a newer CMake. Ubuntu 20.04's 3.16 is not enough.
